# 计算子系统：结构验收与 ME 接入

计算子系统默认用 StructureLib 1.4.47 验证与投影仪共用的结构定义。区块加载和邻居通知在服务端 tick 尾合并；未加载的位置不会被当作有效部件，也不会为检测强加载区块。已有自定义计算器的 addon 可继续使用自己的验收规则。

## ME 接线

- 所有拓扑模式下，只有成型后的计算子系统通讯接口可接外部 ME 线缆。旧存档中接到主机、外壳或其他部件的线缆需要改接到通讯接口。
- 紧凑模式下，结构成型后只有通讯接口持有一个原生 ME 节点，即使没有接线。主机不持有节点，而是通过接口访问 ME 网络；GTNL 无线频率卡应绑定通讯接口。
- 通讯接口可从多个面接入，不再因此回退到逐部件拓扑。AE2 原生处理连接、频道与安全；各部件的待机耗电汇总到通讯接口。不支持延迟注册节点的扩展部件仍使用逐部件拓扑。
- 同一控制器上的有效部件替换或扩缩优先保留运行中 CPU；移除承载该订单的线程核心或计算字节不足时，仍执行取消和库存回收。临时卸载走保存和恢复路径，挂起时不主动取消请求方的链接，但仍受 AE2 原生的请求超时规则约束。切换方式前请先备份存档并在副本验收。

## 调用链与批处理边界

- 首次成型时，`MBCalculator.tick` 发现边界并查找主机，再由 `NEStructureShape.check` 验收。已成型的计算主机优先用现有簇的边界和镜像方向复查，确认外沿、既有成员和蓝图后复用当前簇。外沿变化、成员替换或校验失败时，重新发现结构，再创建、调整或拆除簇。
- AE2 `rv3-beta-1095-GTNH`：`AENetworkProxy.setValidSides` → `GridNode.updateState` → `FindConnections`。新增边可能合并网络；`GridConnection.destroy` 除了标记待寻路，还同步调用两端的 `validateGrid` 检查连通性。`MULTIBLOCK` 用于共享频道分配，原生合成 CPU 也用它；并不把多个节点变成一个节点。
- `PathGridCache.addNode/removeNode` 和连接变化会触发 `repath()`。它只标记待更新；`onUpdateTick()` 才分配频道，有在线 ME 控制器时走 `PathingCalculation.compute()`。因此不要把 `repath()` 次数当作实际寻路次数。
- `CraftingGridCache.pauseRebuilds()/unpauseRebuilds()` 合并样板缓存重建，不暂停拓扑拆分、供电或频道计算。ECO 另按 grid 合并 CPU 列表失效事件。这两类缓存应分别观察。

## 性能对照

在相同的存档副本上，修改 `config/neoecoae.cfg` 的 `multiblock.computationTopologyMode`，重新启动服务端后复现同一批区块加载或结构变动：

| 模式 | 检测 | 接入 |
| --- | --- | --- |
| `LEGACY` | 原有逐成员检测 | 逐部件保留节点，仅通讯接口对外接线 |
| `BATCHED` | 合并检测 | 逐部件保留节点，仅通讯接口对外接线 |
| `STRUCTURE_LIB` | 合并检测并共享 StructureLib 验收 | 逐部件保留节点，仅通讯接口对外接线 |
| `OPTIMIZED`（默认） | 合并检测并共享 StructureLib 验收 | 成型后仅通讯接口持有节点、有效变更保留现有簇 |

四种模式共用部分无变化过滤和缓存事件优化；`LEGACY` 不等同于改动前的 JAR。只比较 StructureLib 验收开销时，使用 `BATCHED` 和 `STRUCTURE_LIB`；对比整套优化时，另外用改动前的 JAR 作基线。

可在 JVM 加 `-Dneoecoae.profileMultiblocks=true`，短时间记录检测次数和耗时；5 ms 预算在两次检测之间检查，不是单次检测的耗时上限。日志本身会增加开销；正式对比峰值 MSPT 时关闭该选项，用同样的采样配置。服务端 `/debug start` 与 `/debug stop` 可查看 `ecoStructureCheck`、`ecoStructureValidation`、`ecoCompactTopology` 和 `ecoComputationGroups`。

记录主线程 MSPT、ME 网络拆分/合并、频道重新分配、合成样板与 CPU 缓存刷新。若服务端 tick 未明显变慢而终端/CPU 离线，优先检查拓扑和频道；若 MSPT 同时尖峰，按采样栈区分结构检测、图遍历和缓存刷新。小型隔离服能验证节点与生命周期，不足以判断玩家存档里数秒停顿的根因。

最低验证矩阵：普通与镜像布局、跨区块加载、低等级核心、两类交换器、外壳旧接线不再连接、通讯接口单面与多面接入、无物理线缆时使用 GTNL 无线频率卡、安全终端、运行中玩家与机器订单。以连接关系、有效频道、耗电、任务库存与结果回填为正确性基线，再比较 MSPT。

## 存储单节点实验模式

存储与合成复用服务端结构检测队列，不再在每个部件加载时做两次同步检测。合成仍用逐部件拓扑；混合拓扑等存储通过存档验收后再做。大型工作站不切换拓扑。

在 `config/neoecoae.cfg` 的 `multiblock` 中设置 `B:compactStorageGrid=true` 并重启世界。默认关闭。启用后仅通讯接口可连接外部 ME；原先接到主机、驱动器、外壳或能源元件的线，以及经这些部件贴邻连通的网络，必须先改接。成型时若发现非接口部件旁有 ME 设备，服务端日志会给出坐标；这只是接线风险提示，不代表该侧一定曾经连通。含不支持延迟节点的部件时整簇回退到逐部件节点。

通讯接口统一挂载驱动器与无限存储的库存，沿用原有挂载优先级、迁移锁和传输模式。能源仍保存在各能源元件内，接口只汇总能量与耗电。能源成员变化时，旧接口节点在变更成员之前退出 AE2，AE2 会在新节点加入时重新读取容量。真实失效或卸载仍立即拆除节点，暂不保留会供电或连通网络的失效接口。

用同一存档制作两个副本，以相同 JAR、区块加载范围及接线分别运行关闭和开启模式；如需测量批量检测本身的收益，再加入改动前 JAR 作为基线：

| 场景 | 验收项 |
| --- | --- |
| 成型、跨区块卸载与加载 | 结构和库存恢复；单节点模式下未成型时无节点，成型后只有接口节点；没有幽灵连接 |
| 拆除/加回能源、驱动器或外壳 | 拆除后旧挂载和旧容量消失；重建后总容量、已存电量、待机耗电及库存符合预期 |
| 接口断线与重连、外壳旧接线、多个接口面接入 | 只有接口能接线；频道、安全终端权限以及相邻机器的连通性正确 |
| 混装物品/流体单元、优先级、创造供应及无限存储 | 原有优先级、精确订单的创造供给、封存状态、传输模式与物资数量不变 |

单独记录 MSPT（中位数、P95、峰值）、结构检测次数，以及 AE2 `GridStorageCache.cellUpdate` 的实际调用次数。AE2 原生节点进出和供电/频道变化仍会触发刷新，不以「恰好一次」作为通过条件。当前没有存档实测数据。
