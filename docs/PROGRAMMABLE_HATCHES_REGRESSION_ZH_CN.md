# 编程舱投料回归

在独立测试存档用 GTNH 2.9.0、编程舱 0.2.1p2 和当前 ECO JAR 运行。ECO 规划与 AE2 规划各跑一轮；有差异时再用原版 AE2 CPU 对照。记录舱的种类、主从关系、样板倍率、待收数量和两端库存，不只看 CPU 页面是否在动。

| 场景 | 操作与通过条件 |
| --- | --- |
| 24 个缓冲 | 对普通、双页、仅物品、Super 和自动样板舱多次提交同一配方，改变订单量但不改样板。不同订单量应共用同一份量记录，不为每个批量开新缓冲。另以 24 种不同配方填满缓冲，再投第 25 种：若进入暂存区，只能接收这一份；释放缓冲后继续且不重复。 |
| 主从共仓 | 主舱和映射从舱各提交同一配方，观察两边共用的缓冲和暂存区。主舱有手动残料时两边均不能吞料；清空后应继续。循环主舱保持原有单份路径。 |
| 部分接收 | 让目标缓冲只够再接 3 份，提交 10 份。ECO 只登记已接收份数的产物，余料留在 CPU 库存，且余份不计投料能耗。清空缓冲后应补发，不多发、不少发。 |
| 关闭快速投料 | 在编程舱配置中关闭 `Fast PatternDualInputHatch` 后重启。普通舱和映射从舱仍能单份投料，批量拒绝后不额外消耗一份。 |
| 间接目标 | 让 ME 接口、P2P 接口和接口覆盖板分别面对缓冲舱、方块请求隧道、部件请求隧道。开启样板优化也只发一份；隧道的已收投料和待回产物一致。换成普通目标后，原生接口仍保留批量。 |
| 纯电路 | 打开舱的编程模式，用只含编程电路的样板重复投料。其他缓冲仍可使用；不计量电路不能把缓冲误报为满。小型、大型电路供应器另用空输入大单验证，观察普通回流、装芯片的启动交付，以及启动时 ME 库存为零的情况。 |
| #26 升级芯片 | 清空电路库存，用需要大量编程电路的下游订单复测。ECO 快速规划下，活跃且装有芯片的大型提供器应把电路直接交给当前 CPU，不占普通派发额度。未装芯片、提供器离线或直接下单电路时仍走原有派发。并列放置未装芯片的提供器，确认不会抢先走普通派发。 |
| #22 加工替换与编程电路 | 开启 ECO 快速规划，清空目标编程电路库存并保留电路供应器。在目标的合成树中放入勾选替换的加工样板，让其消耗该电路。关闭替换规划时提供精确原料，验证 ECO 算出电路子任务并能提交。开启替换规划时只提供可替换的普通原料，分别用 AE2 轻量开关开启及关闭的设置下单，验证 AE2 完整规划能算出替换原料并让 ECO CPU 完成订单。 |
| 保留行为 | 循环舱、概率样板、自动填充器 MKII、多方块代理仍按单份投料。运行中的样板不要改倍率；旧订单仍绑定原样板身份。遇到 `No valid recipe found` 时，记录控制器、配方图、输入模式和实到原料，用原版 CPU 单份复现以区分配方匹配与投料问题。 |
