# 原生加工派发回归

使用独立 GTNH 测试存档并记录实际加载的 ECO、AE2、GT、GTNL 版本。每轮记录 ME 库存、供应器缓存、已发次数和实际回流量；不要只看 CPU 进度条。

| 场景 | 操作与通过条件 |
| --- | --- |
| ME 雕刻机 | 并行分别设为 1、64。以样板执行次数提交 1、2、1000 份（终端下单量 = 每份产量 × 份数）。清空缓存起跑，核对实扣与实收相等。分别记录批量份数接口正常、缺失或回读不一致时的行为：不支持批量则只尝试单份，拒收不得扣料。 |
| 超级样板总成与镜像 | 分别使用纯物品、纯流体及混合样板，与同配方的 GT 总成对照。镜像必须连到对应主总成，样板仍由主总成发布。观察同次发入的份数、机器并行及实收产物。开关超级总成的样板优化，确认它不改变 ECO 翻倍，单种物料的投料量仍受 `int` 上限约束。 |
| 重启与重建 | 让雕刻机或装配矩阵只完成一部分，再停服、重启。保持样板不变时应继续原任务；同设置触发样板重建后也应继续。分别切换雕刻机并行、雕刻物品和矩阵倍率，旧任务不应投给新样板，状态页应提示恢复旧样板或取消后重规划。恢复旧设置时核对没重发已接收的份数。 |
| 普通投料与状态 | 让原生接口分别关闭样板优化和开启合成锁，确认每次仍只投一份；合成锁按原条件解锁。关闭智能翻倍，分别用 0 和多个协处理器核对状态页的派发上限。将编程舱、P2P 接口、流体自动填充器、普通 GT 总成及 GTSWN 矩阵与现有版本对照，不能把特殊的单份行为误当批量。 |
| #7：接口接普通 GT 总线 | 预填总线，只让第一种原料有空间；用包含两种原料的样板逐次提高订单量。记录总线实收、AE2 接口发送缓存和控制器能否启动；和清空总线时对照。多面目标与单面分别跑，复现后才改容量策略。 |
| #10：GT 总成抽样板 | 用装着该样板的普通 GT 总成启动有剩余份数的订单；在 ECO 已选定供应器、GT 尚未插入物料时移除样板。可用调试断点在同一游戏线程精确命中这个窗口。记录 GT 拒收或异常、ECO 的所有权日志及两边库存；放回样板后检查是否续单。只在确认 GT 未接收任何物料的位置修正拒收，不能把派发中的任意空指针当作拒收。 |
