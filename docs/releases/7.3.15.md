## 中文

Minecraft 1.7.10 / GTNH，支持 **GTNH 2.9.0-RC1 及以上版本**。

### 从 7.3.14 升级

- **存储子系统默认使用单节点。** 连接到主机、驱动器、外壳或能源元件的旧 ME 线缆，以及经这些部件贴邻连通的网络，都需要改接到通讯接口。合成样板总线与大型工作站的接线不变。
- 无限存储沿用 7.3.14 的存档格式。建议先备份存档，在副本上检查接线和库存再升级。

### 存储

- 无限存储迁移完成后，取出的成员矩阵变回普通空盘，可用任意合格的空 L9 矩阵替换。少于 12 张成员矩阵或 64 个无限存储组件时暂停访问库存，补齐即可恢复。
- 回填开始后仍锁定原目标矩阵，并在确认目标已存盘后写入回填计划。
- 保护驱动器元件写回；存储接口保留未确认的转移记录，按回执结算物资与能耗。
- 存储与合成子系统在服务端 Tick 末尾合并结构检测。

### 合成、工作站与兼容

- 修复替换样板路由与编程电路占位输入，优化规划中的路由重试。按供应器实收份数结算加工派发，修复编程舱的纯电路缓冲。
- ECO 快速规划支持大型编程电路提供器的升级芯片，将依赖电路直接交给当前 CPU（#26）。梦魇工业合成中心按份派发，不再把单份接收当成整批结算（#27）。
- 样板自动上传按输入总线预放的非消耗模具匹配目标；无电路配方避开已设置固定电路的目标。
- 修复合成 CPU、合成线程与工作站的交付、退款和存档恢复。合成状态页优先显示交付受阻的成品及数量。
- 修复重复样板返还空白样板的结算和打开任务管理界面时的崩溃，兼容 Apeiron 的大整数 CPU 容量读取。

## English

Minecraft 1.7.10 / GTNH. Supports **GTNH 2.9.0-RC1 and later**.

### Upgrading from 7.3.14

- **Storage subsystems now use one ME node by default.** Move existing ME cables and neighboring network connections from the host, drives, casings, and energy cells to the communication interface. Crafting pattern buses and large workstations are wired as before.
- Infinite storage retains the 7.3.14 save format. Back up your world and verify wiring and inventory in a copy before upgrading.

### Storage

- After migration, removing an infinite-storage member returns an ordinary empty matrix. Any eligible empty L9 matrix can replace it. Inventory access pauses below 12 members or 64 Infinite Storage Components and resumes once both requirements are met.
- Restoration still requires the original target matrices once it starts. The restore plan is recorded only after the target saves are confirmed.
- Protect drive cell writeback and retain unconfirmed interface transfers until resources and energy can be settled from receipts.
- Batch storage and crafting multiblock structure checks at the end of each server tick.

### Crafting, workstations, and compatibility

- Fix substitution routing and programming-circuit placeholders, and streamline route retries. Account for the batches providers accept and fix circuit-only buffering in programming chambers.
- Support the large programming circuit provider upgrade chip in ECO fast planning by delivering dependency circuits directly to the current CPU (#26). Dispatch single copies to the Nightmare Industrial Crafting Center instead of settling one accepted copy as a full batch (#27).
- Match pattern upload targets against non-consumable molds already in input buses. Recipes without circuits avoid targets configured with a fixed circuit.
- Fix delivery, refunds, and save recovery for crafting CPUs, crafting threads, and workstations. The crafting status screen prioritizes finished output awaiting delivery and shows its quantity.
- Fix blank-pattern refunds for duplicates and a crash when opening task management. Support Apeiron's arbitrary-precision CPU capacity queries.
