## 中文

Minecraft 1.7.10 / GTNH，支持 **GTNH 2.9.0-RC1 及以上版本**。

### 新增与改进

- 支持原生扩展资源键、精确库存统计、网络存储与合成目录，补全无库存和无样板的可发射资源。
- 单方块集成工作站新增 CraftTweaker 配方接口，两种工作站的脚本配方独立管理，并支持重载刷新。
- 接入 TecTech 多方块、太空电梯及模块的加工状态监控。
- 合成状态页同时显示累计产物进度和当前机器周期进度；加工时间按时、分、秒显示，并读取当前配方的实际并行数。
- 计算子系统在服务端 tick 尾批量处理结构检测，复用 StructureLib 的结构定义，并提供四种拓扑模式用于对照。
- 单点接入的计算子系统按需保留 ME 节点，兼容旧部件接线；多点接入保留原生拓扑，部件待机耗电汇总到主机。

### 修复

- 修复材料合成结束后，库存条目和悬浮提示仍显示 100% 累计进度条的问题；等待材料期间继续显示进度。
- 修复 ME 流体自动装填器卡合成，恢复逐份投料。
- 修复装配矩阵批量投料、稀疏输入槽位及容器返还数量。
- 修复追加订单、重规划与存档恢复后的累计进度统计；等待材料时保留累计进度条。
- 有效结构变更优先保留运行中的合成 CPU，完善线程核心移除、容量结算、区块卸载恢复与 CPU 列表刷新。

### 接线说明

建议通过计算主机或计算通讯端口单点接入 ME。多路接入继续使用原生逐部件拓扑；更改接线或拓扑模式前请备份存档。性能收益取决于实际结构和网络，尚未完成玩家存档内的性能验收。

加工适配参考 salieelinar 的适配改动，并修正批量桥接与进度统计。

## English

Minecraft 1.7.10 / GTNH. Supports **GTNH 2.9.0-RC1 and later**.

### Added and improved

- Added native extended resource keys, exact inventory accounting, network storage, and crafting catalog entries, including emittable resources without stock or patterns.
- Added CraftTweaker recipes for the single-block Integrated Workstation, with separate recipe registries for both workstation types and recipe reload support.
- Added processing status monitoring for TecTech multiblocks, the Space Elevator, and its modules.
- Crafting status now shows cumulative output progress alongside the current machine cycle. Processing durations use hours, minutes, and seconds, with actual recipe parallelism where available.
- Computation structures batch validation at the end of server ticks, share their StructureLib construction definition, and offer four topology modes for comparison.
- Single-ingress computation structures retain only the required ME nodes while supporting legacy wiring. Multiple ingress points retain native topology, and component idle power is aggregated onto the controller.

### Fixed

- Fixed completed materials retaining a 100% cumulative progress bar in stored entries and tooltips. Progress remains visible while waiting for materials.
- Fixed stalled crafting with the ME Fluid Auto-Filler by restoring single-copy dispatch.
- Fixed Assembly Matrix batch inputs, sparse input slots, and container return amounts.
- Fixed cumulative progress after extending orders, replanning, and save restoration. Cumulative progress remains visible while waiting for materials.
- Valid structure changes preserve running crafting CPUs where possible, with improved thread-core removal, capacity settlement, chunk unload recovery, and CPU list updates.

### Wiring notes

A single ME connection through the computation controller or communication port is recommended. Multiple ingress points retain native per-part topology. Back up the world before changing wiring or topology modes. Performance gains depend on the actual structures and network; performance validation in player worlds remains pending.

Processing integration is based in part on salieelinar's adaptation, with additional batch bridging and progress accounting fixes.
