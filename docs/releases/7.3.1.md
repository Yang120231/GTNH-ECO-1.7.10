# Neo ECO AE Extension 7.3.1 · Minecraft 1.7.10 / GTNH

Neo ECO AE Extension 为 Applied Energistics 2 提供面向大型自动化网络的多方块设备。它将**存储、合成执行和合成计算**分为三套可以独立扩展的系统，并提供 L4、L6、L9 三个等级，适合从集中存储逐步发展到大规模批量制造。

本项目是 Neo ECO AE Extension 的 Minecraft 1.7.10 / GTNH 移植版，配方、界面与网络接入使用对应平台的实现。

## ECO 存储系统

为 ME 网络提供可扩展的物品与流体存储。

- 由存储主机、ECO 驱动器、通讯接口、能量元件、散热器和结构外壳组成，可以沿长度方向扩建。
- 物品与流体存储矩阵各有 **16 MiB、64 MiB、256 MiB** 三档，通过 ECO 驱动器接入存储系统。
- 主机界面集中查看矩阵、容量、资源分布与能量状态，并管理存储优先级。
- 通讯接口支持存储、输入和输出模式，可按资源过滤，在本机矩阵与 ME 网络之间转移库存。
- L9 系统提供无限存储模式及库存迁移、恢复功能。满足成员矩阵与组件要求后，可将库存迁入主机存储域。

**适合用途：**集中管理大量物品和流体，扩充生产线仓储，并为大型合成任务提供持续的材料供应。

## ECO 合成系统

承担样板的实际执行，通过多个工作核心并行完成批量合成。

- 样板总线存放合成样板，FX 工作核心提供独立执行通道，并行核心扩充处理能力。
- 合成通讯接口连接 ME 网络，并提供样板集中查看与管理入口。
- 超频与主动冷却用于提高吞吐；流体输入仓、输出仓和散热部件共同支持冷却循环。
- 批量执行减少重复派发，让大量相同配方能够集中处理。
- F9 主机可通过普通或高能网络交换模块组成逻辑合成网络，共享样板域并分配工作。

**适合用途：**大量基础材料、组件和中间产物的持续制造，为大型生产线减少重复合成的等待时间。

## ECO 计算系统

作为 ME 网络中的合成 CPU，为任务提供线程、加速器与任务存储。

- 线程核心决定能够同时运行的任务数量，并行核心提供合成加速能力，计算驱动器与计算单元提供任务存储空间。
- 成型并接入 ME 网络后，可在合成请求中选择 ECO CPU；主机界面提供任务、线程、存储和运行状态信息。
- 支持 ECO 快速规划、循环路线处理和大订单规划；确认界面展示材料需求与规划结果，规划图用于查看配方之间的依赖关系。
- 智能翻倍可配合样板与批量任务使用，减少大量相同配方的重复调度。
- CPU 选择模式可以区分玩家请求与自动请求，便于安排网络中的任务分工。
- C9 主机可通过网络交换模块组成逻辑计算网络，聚合多台主机的计算资源。

**适合用途：**同时运行多个订单，管理复杂配方链，并为高吞吐合成设备持续提供任务。

## 配套设备与使用方式

- **集成工作站与大型集成工作站：**加工 ECO 材料、存储组件和机器部件，支持物品、流体与批量加工。
- **自动搭建面板：**查看多方块结构、材料需求并辅助搭建与扩展。
- **NEI 与 WAILA：**查询相关配方；安装 WAILA 时可查看机器、存储与运行状态提示。
- **GregTech 配方接入：**检测到 GregTech 后启用对应配方与机器加工接入；未安装时保留独立配方。

三套系统通过 ME 网络协作：**存储系统保存材料，计算系统规划与调度任务，合成系统执行样板。**也可以按实际需求单独搭建其中一套，再逐步扩展。

## 运行环境与下载

- **Minecraft：**1.7.10，Forge 10.13.4.1614，面向 GTNH 环境。
- **必要依赖：**GTNH Applied Energistics 2、ModularUI 2、GTNHLib。构建与开发验证使用 AE2 `rv3-beta-990-GTNH`、ModularUI 2 `2.3.49-1.7.10`，GTNHLib 实际解析版本为 `0.11.37`。
- **可选接入：**GregTech、WAILA、NEI、GuideNH；具体功能取决于已安装的模组。
- **安装文件：**下载 **`neoecoae-7.3.1.jar`**，放入客户端与服务端的 `mods` 文件夹，并移除旧版 ECO JAR，避免重复加载。
- `-dev.jar` 用于开发依赖，`-sources.jar` 为源码包，普通游戏安装使用不带这两个后缀的 JAR。
