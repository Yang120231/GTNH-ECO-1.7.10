## 中文

Minecraft 1.7.10 / GTNH，7.3.8 测试版本。

### 修复

- 合成卡请求的成品全部交付、所有步骤派发完毕后，不再因可选副产物未返回而无法收尾；请求方只接收部分成品时继续等待。
- 自动追踪绑定实际执行任务的 ECO CPU，接入 GTNH 原生合成完成通知监听器，并保存追踪状态。
- ECO 多方块 NEI 预览补充长度与镜像频道，接入现有的复制频道到手持全息投影仪按钮。
- 补齐原版规划执行路径对可编程仓室空输入样板的兼容，避免将零数量占位物品当作真实原料提取。

### 验证范围

- 已通过自动化测试与构建；弹窗、聊天提示、NEI 复制操作及具体机器投料链路仍待游戏内复测。
- 客户端与服务端请同步更新。

## English

Minecraft 1.7.10 / GTNH. Beta build for 7.3.8.

### Fixed

- Machine requests now finish after all steps are dispatched and the requested output is delivered, without waiting indefinitely for optional byproducts. Partial output delivery keeps the job active.
- Automatic tracking follows the ECO CPU that actually runs the job, invokes GTNH's native completion listeners, and persists follow state.
- Added length and mirror channels to ECO multiblock NEI previews for the existing copy-to-held-hologram-projector button.
- Added input-less Programmable Hatches pattern support to the native-planner execution path, avoiding extraction of zero-sized placeholder ingredients.

### Validation scope

- Automated tests and builds have passed. Notifications, NEI channel copying, and the reported machine input chain still require in-game verification.
- Update both client and server.
