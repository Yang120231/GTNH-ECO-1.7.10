# 样板上传来源与绑定

非 GT 接收端的 `ROUTED` 表示 NEI 来源与关联机器相符，并不表示机器实际核验过该配方。IC2 专用配方核验尚未接入。

## 绑定与提示

服务器逐行计算能否绑定和拒绝原因，列表与保存共用检查。一个工作站具有类别，不再使其他没有来源类别的 IC2 接收端也可点击绑定。
缺少类别、目标变化、离线、匹配冲突、信息过长和映射数量超限分别显示对应原因。
既有映射在所有接收端离线或映射数量已满时仍可停用、删除。

标题分别显示“NEI 来源”“推断自”或普通“类别”。目标提供的类别不会显示为 NEI 来源。

## 编辑与恢复

NEI 填入包处理完成后，在服务器记录终端实际输入和产物的快照，包括槽位、数量、流体及 NBT。编码时再次比对，因此替代材料、填入倍数和副产物都以实际填入结果为准。
发生变化后仅保留类别，关联机器不再使该样板获得 `ROUTED`；需要玩家显式绑定后才可向未验证接收端自动上传。重新从 NEI 填入可以重新建立依据。
GT 和工作站已有的真实配方核验仍可独立确认合法配方。

成功编码的来源保存在玩家持久化数据中，不修改样板 NBT。复用现有 `samePattern` 比较，忽略顶层编码时间，保留其他物品和 NBT 差异。
每玩家最多保存 128 条；单条最多 16384 个 NBT 文本字符，总计最多 262144 个字符，优先保留最近编码的来源。超限项不缓存。
关闭终端、重新登录后，再放入缓存命中的样板可以恢复来源与类别。不同玩家的缓存彼此独立。
升级前从未记录过来源或已被淘汰的旧样板无法凭空恢复，需要重新从 NEI 填入。

未验证绑定的签名包含接口朝向上的机器类、方块、元数据和机器物品形式（含 NBT），更换这些信息后必须重新绑定。旧的空签名绑定也需重新绑定。
GT 来源绑定到无法核验的非 GT 机器时，列表和保存结果均显示警告。

## 待游戏内验证

以下是验收步骤及源码预期，并非已完成的游戏验证。使用同一台 IC2 打粉机和正对它的接口面板。

| 操作 | 预期 |
| --- | --- |
| 原生配方从 Macerator 页填入并编码 | NEI 来源、关联机器命中、ROUTED，可绑定及自动上传 |
| 自定义配方加入同一 IC2 配方管理器并从该页填入 | 与原生配方相同 |
| 没有任何历史来源的样板，手动摆放并编码 | 缺少 NEI 来源，不能绑定该 IC2 接收端；普通手动上传仍按现有规则可用 |
| 将已记录来源的样板关闭终端后重新放入，或重新登录后放入 | 恢复来源与映射 |
| NEI 填入后改变一个输入、输出、数量或 NBT，再编码 | 仅类别、未验证；原自动记忆映射不再匹配，显式绑定后才可按类别投递 |
| 将未验证目标显式绑定，再换成另一种机器 | 签名变化，自动上传要求重新绑定 |
| GT 配方来源绑定 IC2 打粉机 | 未验证，列表及保存结果提示跨机器核验警告 |
| 无关联机器的自定义 Handler | 显示未注册关联机器，可显式绑定 |
| 接口转离所有机器 | 显示朝向没有机器；已经保存的绑定签名改变 |
| 无来源的盈能水晶样板同时列出工作站和 IC2 | 类别标注为推断自工作站；仅工作站可绑定，IC2 显示缺少来源 |
| 目标全部离线或映射数量满 | 准确显示拒绝原因，既有映射仍可停用、删除 |
| 超过 64 个接收端 | 分包后每行绑定权限和拒绝原因均对应原行 |

客户端与服务器应同时更新，以使用新的逐行绑定信息。
