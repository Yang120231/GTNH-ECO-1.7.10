# 1.7.10 网络交换接入修复

## 来源与问题

对照已检查远端的 1.21.1 源码 `1c1e084b5669a09c950d333ce4c43b2ba3355f15`，并核对本项目实际依赖 GTNH AE2 `rv3-beta-990-GTNH` 的事件和频道分配实现。

本项目已有交换方块、结构校验和逻辑组计算，但原生节点桥接缺少 `MENetworkBootingStatusChange`。AE2 重新寻路时，即使频道数不变，节点的 `isActive()` 也会经历离线和上线；此时不保证再发频道变化事件，原有逻辑组可能无法重建。

另外，计算主机的频率仍采用 1–4096 范围，与来源的四频率循环不一致。手动调整频率后的组变化也没有主动通知 AE2 重新发布 CPU 列表。

## 本次接入

- 将 AE2 启动状态变化接入现有节点监听器，在服务器 tick 末尾完成逻辑组刷新，支持启动完成和重新寻路后的重连。
- 计算主机采用与合成主机相同的 1–4 频率循环；自动分配保留玩家已有的有效频率。
- 计算组重建完成后，每个 ME 网络通知一次 CPU 列表刷新；退出交换组也会通知刷新。
- 使用现有高版本共享计算：合成组共享可调度工作线程；计算组共享存储、线程和并行能力。

使用条件保持来源规则：L9 主机，在正确位置安装对应子系统的交换模块；同维度、同 ME 网络、同频率的至少两台主机才组成共享组，每组最多八台。合成组与计算组分别管理。计算组普通模块按自身资源 ×2、高能模块按自身资源 ×8 后汇总。

## 验证

`NativeNetworkSwitchTest` 的四项回归测试覆盖：

1. 通过实际依赖的 AE2 事件总线投递启动完成事件，验证合成工作线程共享、网络重启拆组和重连。
2. 通过实际 AE2 事件总线验证计算资源汇总；两个各有 100 字节、4 线程、64 并行的主机分别安装普通和高能模块，得到 1000 字节、40 线程、640 并行。切换频率会拆组、刷新 CPU 列表，恢复同频率后重新合组；世界清理会解除关联。
3. 验证八台上限，以及 ME 网络、频率、维度和未安装交换模块的隔离。
4. 验证计算主机的 1–4 循环和自动分配不覆盖玩家设置。

完整执行 `test build -PplannerChallenge=true --offline --console=plain --continue`：686 项测试中 685 项通过；唯一失败为当前工作区已有的大型工作站页面缺少翻译键。全仓 Checkstyle 和 Spotless 仍有既有错误；本次不改动这些无关代码。编译、开发包、安装包和源码包生成成功。

最终专项复验：四项回归测试通过；三个生产文件和一个测试文件的 Checkstyle 零错误，四个文件的 Spotless 均为 `IS CLEAN`。重新生成的安装包、开发包均包含启动事件处理代码，三个变更类均为 Java 8 字节码；源码包内容与当前源码逐字节一致。安装包为 `build/libs/neoecoae-0.1.0-porting.jar`。
