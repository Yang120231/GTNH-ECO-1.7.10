## 审查方法

方块注册与档位 → 方块实体创建 → 多方块成型 → 网络节点接入 → 交换器注册 → 频率分配与分组 → 逻辑网络/集群重建 → 控制器与 CPU/运算资源聚合 → 实际使用端 → UI 同步 → 存档与重载 → 拆除和卸载清理。

## 必须逐项比较的行为

1. **交换器类型和档位**：普通/高能、合成/运算交换器的注册与创建是否正确；连接对象、数量限制、容量或倍率、能耗等规则分别是什么。所有数值必须从源码得出，不能凭名称推断。
2. **网络边界**：物理 AE2 网络与 ECO 逻辑网络是什么关系；同频是否还受物理网络、维度、类型、拥有者或其他条件约束；不同频率是否正确隔离；合成和运算网络是否发生串网。按 1.21.1 的实际规则判断，不预设必须同维度或必须跨维度。
3. **频率分配与修改**：默认值、有效范围、未分配状态、自动分配、冲突处理、频率回收、复用、修改立即生效、错误输入、多人修改，以及重启后是否稳定。区分客户端显示值、服务器有效值与持久化值。
4. **集群与拓扑**：成型、拆除、旋转、连接/断开线缆、断电恢复、区块卸载重载、维度切换、服务器重启时如何加入、离开、拆分、合并和重建；是否有幽灵节点、残留控制器、重复注册和跨存档静态状态污染。
5. **合成资源的实际共享**：同组控制器如何影响 CPU 发布、终端选择、容量与并行能力、任务提交、样板可见性、发配和产物回收。每一项先确认 1.21.1 是否支持，再判定 1.7.10 是否遗漏。重点检查界面显示“共享”但 AE2 服务或实际执行仍按单机运行的情况。
6. **运算资源的实际共享**：运算生产、消费、分配、上限、倍率、能耗和短缺行为；聚合后是否重复计入或完全没有接入使用端；重组网络后是否继续引用旧集群。
7. **高能规则**：倍率作用于什么、如何计算、多交换器是否叠加、作用范围、溢出与精度、能量准入与执行是否一致；不要先调整平衡参数掩盖机制错误。
8. **生命周期与持久化**：频率和配置的读写、旧存档兼容、加载顺序、未加载成员处理、世界关闭清理、客户端与服务端字段一致性，及卸载后引用泄漏。
9. **AE2 版本适配**：核对 1.7.10 实际 AE2 分支的网格事件、节点生命周期、CraftingCache/服务、CPU 发布和缓存刷新机制。区分不可直接移植的 API 差异与可以保留的玩法行为；Mixin 或适配器存在不代表运行时已触发。
10. **UI 与操作反馈**：交换器配置入口、频率输入/应用、网络成员与能力显示、断线与未成型状态、服务端校验、错误提示、打开界面后重组网络的刷新。跟踪一次玩家操作直到服务端实际效果，再跟踪状态回传。
11. **性能与确定性**：是否每 tick 全服扫描/重建、重复遍历成员、事件风暴、无变化也重发同步、无界缓存；是否依赖 HashMap 顺序导致分配抖动、选主不稳定或重复计算。说明触发规模与实际调用频率，不能只凭代码风格判断性能。
